# Contributing

## Delivery Flow

1. Start from an issue with an observable outcome and Definition of Done.
2. Create a short-lived branch such as `feat/topic`, `fix/topic` or `docs/topic`.
3. Use Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `ci:`, `refactor:` or `chore:`.
4. Open a pull request, complete validation and security sections, and wait for required CI.
5. Merge only a green reviewed change and update the relevant release note.

Never commit credentials, private keys, local state, exports or raw host evidence.
